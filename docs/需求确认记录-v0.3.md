# Release Workbench 需求确认记录 v0.3

日期：2026-10-20。依据用户对 v0.2 样稿的反馈和 Jenkins 列表截图；与旧设计冲突时以本记录及后续用户要求为准。

| 范围 | 已确认结果 |
| --- | --- |
| 运行形式 | Windows 本地 Web，单人单机；当前只做前端样稿 |
| 项目服务 | 创建项目时维护服务、类型、Git、默认分支；项目内可继续添加、编辑 |
| 环境 | 归项目；一个环境可有多台 Linux 服务器，共用一份部署路径，只维护一个 MySQL 连接 |
| 环境连接菜单 | 保存服务器、数据库、文件路径及环境服务的 Job/参数绑定 |
| Jenkins 凭据 | 在全局维护前端/后端两套地址、账号、Token，所有项目和环境共用 |
| 发布入口 | 选择环境、勾选服务，触发已有 Job；不要求选择版本或将版本标记就绪 |
| 分支 | 部分 Job 支持分支参数，发布时按服务选择；其余使用 Job 自身配置 |
| SQL | 每个版本维护 SQL 清单、内容、顺序及变化，由人工执行；工具发布不执行 SQL |
| 配置 | 版本维护文件内容、路径和差异，由人工更新；工具发布不修改配置 |
| 备份 | 独立保留资料页；不属于 Jenkins 自动发布流程，不新增自动备份或恢复 |
| 版本 | 可跨环境参考，默认 YYYYMMDD-01 后缀递增；服务从项目清单选择，记录本版本分支、提交及产物 |
| 外部 AI | 项目不调用模型；后续允许外部 AI 查询资料并调用相同的 Jenkins 发布入口，不提供 SQL 执行或配置更新接口 |
| 阶段边界 | 真实 Jenkins 参数读取、调用、日志获取、凭据保存和 AI 接口等到新版页面确认后实现 |

界面使用虚构项目、地址、账号、分支、队列和构建结果；不从用户截图复制实际连接资料。样稿的分支选项手动维护，尚未读取真实 Jenkins。
