# Release Workbench 前端调整计划 v0.3

日期：2026-10-20

状态：用户已通过 Jenkins 列表截图确认方向，并补充部分 Job 支持选择分支；本次仅调整前端样稿。

## 一、问题确认

当前页面把服务仓库重复维护在版本内，把 Jenkins 账号放在环境内，并将备份、执行 SQL、更新配置纳入发布步骤，与实际使用方式不符。

## 二、调整后的结果

### 项目与服务

新建项目时可填写项目包含的服务：服务名称、前端/后端类型、Git 地址和默认分支。项目详情增加“服务管理”和“添加服务”入口，后续可继续补充、编辑。

版本从项目服务清单中选择本次涉及的服务，记录本次分支、提交等变化；Git 地址引用项目中的资料，无需重复填写。原“组件仓库”改为“版本服务”。

### 项目内的环境

每个环境明确归属于一个项目。环境连接页面继续保存环境配置信息：可增删多台 Linux 服务器，每台维护连接信息；环境统一维护一份部署路径，供该环境内所有服务器共用；每个环境只维护一个 MySQL 连接。

配置文件目录和其他已有路径继续作为环境资料保存。

### 全局 Jenkins

增加外层“Jenkins 设置”，集中维护两套共享配置：前端 Jenkins、后端 Jenkins。每套填写地址、账号和 Token，供所有项目、环境引用。

建议在“环境连接 → 服务发布任务”里，将项目服务绑定到对应的 Jenkins Job，并维护该环境所需的 Job 参数。服务按前端/后端类型引用全局账号。同一个 Job 可以绑定多个环境，通过参数区分；不同环境也可以绑定不同 Job。

### 发布操作

“部署 / 预览发布”改为：选择当前项目下的环境 → 勾选一个或多个服务 → 查看对应 Job 和参数 → 发布。页面不要求先选择版本或将版本标记就绪。

工具仅代替人工触发选中服务的 Jenkins Job，随后展示排队、构建结果及日志链接；不自行通过 SSH 更新服务器。实际构建和部署行为由已有 Jenkins Job 决定。

部分 Job 支持分支参数：绑定时登记参数名称与可选分支，发布时逐服务选择分支；不支持的 Job 显示“使用 Job 自身配置”，不强行传入分支。样稿使用示例分支；后端阶段再对接真实 Job 参数。

版本中的 SQL 和配置文件继续维护内容及差异，明确标注“人工执行 / 人工更新”，不进入工具的自动发布步骤。工具自身不执行 SQL、不更新配置，也不在发布流程中自动备份或恢复。

部署记录按环境和所选服务展示各 Job 的结果，允许部分服务成功、部分失败；不能将仅提交到 Jenkins 队列显示为发布成功。

外部 AI 页面同步展示上述边界：后续可读取项目资料并调用相同的 Jenkins 发布入口，不提供 SQL 执行或配置更新能力。

## 三、本期做 / 不做

本期完成上述页面、表单、示例数据和交互演示，并更新离线 HTML 样稿。备份管理作为独立页面暂保留现状，不新增真实操作。

本期不开发后端，不连接真实 Jenkins、服务器或数据库，不开发真实发布、备份、Nacos 同步、Skill 或 MCP。页面输入的示例凭据不持久化。

## 四、前后端改动范围

前端调整项目创建与详情、服务管理、版本服务选择、环境编辑器、全局 Jenkins 设置、发布弹窗、部署记录及 AI 资料导出。同步修改概览、步骤说明和帮助文案，避免保留旧发布流程的误导。

前端数据模型改为项目服务清单、环境服务器列表、全局 Jenkins 配置及环境服务任务绑定；部署记录保存服务级结果。同步更新需求确认记录和样稿说明。

后端无改动。确认后在 test_zy 实现，完成后 cherry-pick 至 test 并同步 GitHub 私有仓库。

## 五、验证方式

运行类型检查及生产构建；通过浏览器验证以下完整路径：

1. 创建项目并维护多个服务，之后能补充服务；新建版本可直接选择已有服务。
2. 环境中维护多台服务器、一个共用部署路径和一个数据库连接，切换项目不会混入其他项目的环境或服务。
3. 全局维护前后端 Jenkins，环境任务绑定能引用相应配置，不重复维护账号。
4. 无版本时也能选择环境和多个服务演示发布；没有任务绑定的服务给出明确提示。
5. 发布预览、模拟记录及 AI 资料不包含自动执行 SQL、更新配置或 SSH 部署步骤；模拟构建结果按服务展示。
6. 桌面与窄屏可用，离线 HTML 可打开，演示不会产生真实业务请求。
