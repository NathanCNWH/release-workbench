# 主机连线与版本服务调整 v0.6

日期：2026-10-21。状态：用户已确认，并补充服务手动拖动排序、修复左上角项目下拉框；按本计划实施。

## 一、问题确认

- 环境页面以服务卡片重复展示整份主机清单，新增主机也强制同时关联服务，独立维护主机的入口缺失。
- 版本页“发布服务”实际展示部署记录，服务数量由已提交的发布任务推导；不能提前登记本版本涉及哪些服务，且多个发布入口混在资料维护页面中。
- 当前项目缺少网关后端。

## 二、调整后的结果

### 环境中的主机与关联

主机可以先独立新增、编辑和保存，没有关联也可保留。环境切换到“服务与主机”后，左列显示项目服务，右列显示当前环境的主机，中间用线展示已有关系。

- 从服务右侧连接点拖到主机左侧连接点即可建立关系，也支持依次点击两端完成关联。
- 一个服务可连多台主机，一台主机可被多个服务连接；重复连接不会重复保存。
- 点击连线可查看两端名称，并选择解除关联；只解除关系会保留主机。删除主机需明确确认，同时清理关联。
- 主机表单使用侧栏或弹窗，避免挤占连线区；关闭未保存修改时提示。当前已保存的主机与关系直接显示为节点和连线。
- SSH 环境变量认证仍不需要填写登录账号。Jenkins Job 在原任务设置入口维护。

### 版本中的涉及服务

版本页的“发布服务”改为“涉及服务”：直接勾选项目已有服务，显示名称、类型和 Git 仓库；搜索、全选、清空以及已选数量均围绕版本资料。

- 新建版本可以不选服务，后续在草稿详情中补选；创建表单也提供可选的服务勾选区。
- 版本列表、概览、导出和外部 AI 上下文展示登记的涉及服务。就绪、归档版本继续只读。
- 移除版本详情顶部、服务页签和操作说明中的“预览发布”“发布此版本”按钮。历史构建结果继续从部署记录追溯。
- 实际发布继续在统一发布入口操作，选择环境、版本资料、服务与分支；版本里的勾选仅记录影响范围，不自动触发发布，也不改变当前发布服务的选择规则。

### 网关后端

在当前项目服务目录新增“网关后端”，类型为后端服务、默认分支 test。使用本地网关仓库已核对的 Git 地址；在 test/prod 环境绑定实际存在的对应 Jenkins Job，主机关联以任务部署日志及现有资料核对后录入，不能从其他服务复制推定。

### 服务顺序与项目切换

服务管理提供拖动排序，顺序按项目保存；环境、版本服务勾选和发布列表沿用该顺序，刷新后不变。提供键盘调整顺序的等效操作。项目切换改为与侧栏一致的下拉列表，清晰显示当前项目，支持鼠标和键盘切换及关闭。

交互样稿位于本机会话 outputs/Release-Workbench-交互确认-v0.6.html，仅使用示例主机、不会写入工作台。

## 三、本期做 / 不做

本期完成上述两个页面的交互、资料保存和网关录入，并保留现有环境、版本资源及历史记录。

不增加自由画布、节点任意拖动、SSH 自动部署或 Jenkins 自动建任务；不执行真实发布、SQL 或配置变更。

## 四、前后端改动范围

- 前端：环境主机编辑与连线组件，版本创建和详情的服务勾选，相关数量、导出及 AI 展示，服务拖动排序和项目切换组件；保留整体视觉风格。
- 后端：版本新增涉及服务 ID 字段及所属项目、去重、引用和状态校验；旧版本字段缺失时按空列表读取，不根据历史发布自动猜测；发布快照保留来源版本当时的登记范围。
- MCP：版本的现有新增、编辑、查询工具支持同一字段，保持与页面一致；服务主机关联沿用现有 bindings[].serverIds 数据关系。
- 文档：同步使用说明、AI 接入资料和当前计划状态；真实网关、环境和连接资料仅进入本地数据，不提交 Git。

## 五、验证方式

- 验证草稿服务勾选、空选择、跨项目服务拒绝、就绪版本限制、旧数据兼容，以及页面、导出、MCP 和发布快照的一致性。
- 验证服务拖动、键盘排序、刷新与重启后的顺序，以及项目下拉展开、选择、关闭和窄屏显示。
