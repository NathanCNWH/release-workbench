# Release Workbench 启动与使用

适用版本：v0.5，本地 Windows，单人单机。

## 启动与停止

项目目录：`D:\git_rep\release-workbench`。

| 操作       | 双击脚本   | 项目目录命令               |
| ---------- | ---------- | -------------------------- |
| 启动前后端 | `启动.cmd` | `npm run start:background` |
| 停止应用   | `停止.cmd` | `npm run stop`             |
| 查看状态   | —          | `npm run status`           |

启动后访问 <http://127.0.0.1:4173/>。脚本在后台运行一个 Node 进程，同时提供业务 API 和构建好的前端页面；启动窗口关闭后，服务仍在运行。停止脚本只操作经过验证的本项目进程。

需要 Node.js 24 或以上版本。启动脚本会按 lock 文件安装依赖、构建前端、等待就绪；重复启动不会再开一个实例。旧的 `启动前端样稿.cmd` 现在也转到同一启动流程。

如需在当前终端运行：先执行 `npm run build`，再执行 `npm start`，在该终端按 **Ctrl+C** 停止。

停止本地应用不会取消已经触发的远端 Jenkins 构建。重启后继续查询已保存的队列和构建；提交阶段中断的任务标为“结果未知”，不会自动重发。

## 第一次使用

1. 新建项目，登记服务、前后端类型、Git 与默认分支。后续可在“服务管理”补充或编辑。
2. 新建项目内环境，只填基本资料即可。在“服务主机 / SSH”中为各服务新增或复用主机，一个服务可关联多台，不同服务可以关联不同主机或复用同一主机。环境共用一份部署路径和一个 MySQL 连接。选择 SSH_NAME / SSH_PWD 认证时不填账号和密码，应用从启动进程读取；密码/私钥认证仍填写账号。保存凭据后输入框清空。
3. 在全局“Jenkins 设置”分别保存前端、后端 Jenkins 地址、账号和 API Token，可点击“检查已保存连接”。
4. 在“环境连接 → 服务发布任务”按服务绑定 Job 路径和固定参数。根任务只填任务名；实际文件夹内的任务填 `folder/job-name`，不包含 Jenkins 视图名或完整 URL。固定参数每行 `NAME=value`。
5. 部分任务支持分支：填写分支参数名和可选分支，或点击“读取 Job 参数”导入其公开的 Choice 选项。Git Parameter 插件没有公开动态选项时，手动维护列表；不支持分支的任务使用 Job 自身配置。
6. 新建版本，只登记版本号和说明；在版本过程中维护 SQL 和配置内容、差异。支持读入 UTF-8 文本文件。就绪后锁定资料，需要修改时复制成新版本。
7. 点击“预览发布”，可勾选本项目多个版本并用上下箭头调整合并顺序。相同 SQL 去重；同数据库同名不同 SQL、同目标路径不同配置会列为冲突，选择保留内容后才能生成预览。再选择环境、服务和分支，核对后触发 Jenkins。可以不选版本独立发布。
8. 查看各服务的排队、构建及最终结果；发布详情保留全部来源版本、最终 SQL/配置、冲突选择和服务主机快照，支持下载资料快照、SQL 清单及配置文件。原版本不被覆盖，也不产生新的合并版本。入队不表示成功，“结果未知”需要先核对远端。

工具只触发已有 Jenkins Job。SQL 由人工执行，配置由人工更新，工具不进行 SSH 部署、不修改配置或执行版本 SQL。Jenkins 成功表示 Job 返回成功，实际业务效果需按该 Job 的实现核验。

项目服务的“默认分支”只用于预填新环境任务。之后以环境任务设置及发布时的选择为准；不支持分支的任务由 Jenkins 自身决定。

旧版环境主机升级后保留为待关联资料，请在每个服务下勾选，不会猜测归属。历史单版本发布记录保留不变。

## 数据与备份

- 业务数据保存在 `data/workbench.sqlite`，使用 SQLite，无需另装数据库服务器。
- 连接秘密用 AES-256-GCM 单独加密；`.master-key` 是本机数据密钥，`.api-token` 用于本机 CLI/MCP。它们与数据库一起保存在被 Git 忽略的 `data/` 中，不提交仓库。
- 迁移整个工作台时，先停止应用再复制完整 `data` 文件夹，必须保留 `.master-key`。页面“备份工作台资料”导出的 JSON 不包含连接凭据；SQL/配置文本保持原样，按业务资料保管。
- MySQL 备份在“备份管理”独立发起，使用本机 `mysqldump`。它生成 `.sql.gz` 文件，只有成功退出并写完文件后才标记完成，同时记录 SHA256。`--single-transaction` 的一致性保证适用于事务表；当前不提供自动恢复。
- 备份文件在 `data/backups/`，支持页面下载。日志在 `data/logs/`，启动日志和错误日志按时间分别保存。

## 外部 AI

应用不调用任何模型。“外部 AI 接入”提供当前机器的 MCP 配置及 Skill 下载。

先启动工作台，再把该页的 stdio MCP 配置加入外部 AI 客户端。服务入口为 `server/mcp.mjs`；它通过本机 API 管理业务资料、合并版本、生成发布预览、触发已授权的 Jenkins 计划及查询结果。Skill 源码为 `integrations/release-workbench/SKILL.md`，没有自动安装到其他客户端。

已有 MCP 配置无需修改服务路径，重启外部 AI 客户端的 MCP 服务或重新加载工具列表即可获得新增工具。连接密码和私钥仍在页面中维护，不通过资料工具读取或写入。

| 工具 | 作用 |
| --- | --- |
| projects_list / project_context | 查询项目和整体上下文 |
| records_list / record_get | 查询六类资料，返回最新 revision |
| record_create / record_update / record_delete | 新增、部分更新、删除；写操作带 revision |
| version_merge | 按顺序合并版本资料、返回冲突与选项 |
| deployment_preview / deployment_run | 冻结预览、按已授权范围触发 Jenkins |
| deployment_get / deployment_logs | 查询结果与日志 |

entity 取 project、service、environment、version、sql、config。除 project 外必须指定 projectId；sql/config 还必须指定 versionId。修改使用最近查询的 revision，出现冲突需重新读取，不能覆盖他人更新。服务器与任务数组需保留原有资料再提交修改。新建版本未指定名称时默认年月日加序号。删除需 confirmed=true；有历史引用的资料和固定版本不允许删除，版本可用 status=已归档归档。SQL/配置操作仅改变版本资料。

给 AI 的示例：“创建一个项目并登记 api、web 服务”“给测试环境的 api 服务关联两台主机”“新建今天的版本，保存这段 SQL 为资料”“合并这两个版本，先给我看冲突，处理后再预览发布”。Skill 下载文件包含字段与使用流程。

## 可选环境变量

| 变量                  | 用途                                             |
| --------------------- | ------------------------------------------------ |
| `RW_PORT`             | 本机服务端口，默认 4173                          |
| `RW_DATA_DIR`         | 数据目录，默认项目下 data                        |
| `RW_MYSQLDUMP`        | mysqldump 可执行文件路径，未配置则从 PATH 查找   |
| `SSH_NAME`、`SSH_PWD` | 服务器选“环境变量认证”时使用，须在启动进程前配置 |

自定义端口或目录时，启动、停止、状态命令使用相同变量。页面提供的 MCP 配置会包含当前数据目录和服务地址；同一数据目录只允许一个应用实例。

开发模式：`npm run dev` 启动前端 5173 和后端 4175，终端 Ctrl+C 停止。日常使用上面的后台启动脚本即可。

## 验证范围

本地持久化、加密存储、服务主机关联、环境变量 SSH 登录、版本合并、MCP 六类资料管理和 Jenkins 生命周期的受控测试已验证。未配置用户真实环境，未实际连接用户 SSH/MySQL，也未发布用户的 Jenkins 项目。

对接依据：[Jenkins Remote Access API](https://www.jenkins.io/doc/book/using/remote-access-api/)、[Jenkins CSRF](https://www.jenkins.io/doc/book/security/csrf-protection/)、[MCP 服务开发文档](https://modelcontextprotocol.io/docs/develop/build-server)。
