# 服务主机、版本合并与 AI 管理计划 v0.5

日期：2026-10-21。状态：用户已确认本次发布清单和快照保留原版本，并扩展项目、服务、环境、版本及 SQL/配置资料的 MCP 管理；按本计划实施。

## 一、问题确认

- 项目服务默认分支只用于初始化环境任务；发布使用该任务的默认分支或当次选择，当前说明不足。
- MCP 已提供项目查询、项目上下文、发布预览、触发、结果和日志六个工具，未提供业务资料增删改查。
- 发布只能关联单个版本，没有多版本合并入口。
- 主机当前归环境统一维护，无法表达不同服务对应不同主机。
- SSH 环境变量认证已在后端读取 SSH_NAME / SSH_PWD，前端和数据校验仍强制填写登录账号。

## 二、调整后的结果

1. 默认分支增加用途说明：服务预设值只初始化新任务，环境任务设置和发布时选择决定本次分支；无分支参数的任务由 Jenkins 自身决定。
2. 新建环境仅填环境基本资料，不要求主机。环境内按服务维护多台主机，服务器可在不同服务间复用；数据库仍为环境内单一连接。部署路径沿用已确认的环境共用规则。
3. 主机选择环境变量认证后，隐藏登录账号、密码输入，直接使用启动进程的 SSH_NAME / SSH_PWD；密码或私钥模式仍填写账号。
4. 点击发布可勾选当前项目的多个版本，预览汇总的 SQL、配置变更，再选择环境、服务、分支并触发 Jenkins。生成本次发布资料快照、保留各来源版本，发布记录能够追溯所有来源。
5. 合并按用户确认的版本顺序组织；重复 SQL 不重复列出，同名不同内容的脚本、同路径不同内容的配置列为冲突，人工明确取舍后才能完成预览；保留来源和最终选择。
6. MCP 支持项目、服务、环境、版本、SQL 和配置资料的查询、新增、编辑、删除或归档。业务资料的修改不代表执行 SQL、更新服务器配置或发布；发布继续使用独立预览与触发工具。

## 三、本期做 / 不做

做上述确认后的页面、数据关系、合并资料快照及 MCP 工具；历史发布保持原快照，已有环境主机不丢失、不自动猜测其服务归属，首次使用时由用户分配。

不合并 Git 分支，不自动执行 SQL、不向服务器同步配置、不进行 SSH 部署、不接入模型或 Nacos。已有引用的资料通过归档或明确引用校验处理，删除不破坏发布历史。

## 四、前后端改动范围

- 前端：服务默认分支提示、环境创建与服务主机编辑、SSH 认证表单、发布版本多选与合并冲突处理、AI 接入说明。
- 后端：服务与主机关联及兼容迁移、条件账号校验、多来源版本快照与合并校验、经确认的 MCP 业务操作与引用检查；同步更新 Skill 文档。

## 五、验证方式

- 创建空主机环境；同一环境两个服务分别关联不同多台主机，允许复用，保存重启后关系保持；旧环境主机保留等待分配。
- 环境变量认证可不填账号，受控 SSH 测试核对实际使用环境变量；其他认证仍验证账号必填。
- 多版本顺序、重复与冲突、原版本保留、历史单版本记录兼容；验证一次发布仅触发所选服务，SQL 和配置均不自动执行。
- 用 MCP 客户端验证所选范围的资料增删改查、引用限制及现有发布工具；前端构建、浏览器检查、启动停止后保留应用运行。
