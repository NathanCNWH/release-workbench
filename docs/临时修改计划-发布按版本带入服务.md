# 发布时按版本自动带入服务

日期：2026-10-22。状态：用户已确认，已完成实现、类型检查、构建、13 项现有后端测试及受控浏览器验证。

## 一、问题确认

用户所说的“版本关联的项目”按版本中勾选的“涉及服务”理解。当前发布窗口选择版本只更新 SQL / 配置汇总，服务选择独立保存，没有读取版本的 serviceIds，因此需要重复勾选。

## 二、调整后的结果

- 选择一个或多个版本，自动勾选这些版本关联服务的并集，重复服务只显示一次，排列沿用项目服务顺序。
- 自动勾选后仍能手动增加或取消服务。增选、取消版本时，按最新版本集合重新生成勾选；取消所有版本时清空服务勾选，之后可手动独立发布。仅调整版本合并顺序不会重置手动选择。
- 切换环境后，按已选版本重新带入可发布服务；未绑定 Job、Jenkins 配置不完整等服务显示未带入原因。未登记涉及服务的版本给出提示，可手动选择。
- 保留已选服务的分支选择；新带入的服务使用当前环境默认分支。最终仍经发布预览确认后触发 Jenkins。

## 三、本期做 / 不做

本期仅调整发布窗口的版本与服务联动和提示。不改版本资料、真实连接配置和历史发布记录，不自动执行 SQL 或同步配置，不触发实际 Jenkins 发布进行验证。

## 四、前后端改动范围

- 前端：LivePublishDialog 的勾选初始化、版本变更和环境切换逻辑；VersionPicker 说明文字及未带入服务提示。
- 后端：沿用现有版本 serviceIds 和发布接口，无数据库迁移，不改变 MCP 参数含义。
- 同步项目协作及使用说明；确认实施后构建、重启本地工具，并提交推送 main。

## 五、验证方式

类型检查及构建通过；用虚构项目和 Mock Jenkins 验证多版本去重、版本增减、手动增减、调整版本顺序、切换环境、缺少 Job、空服务版本，以及返回修改保留选择。确认预览只包含最终勾选服务，关闭窗口不触发构建。

## 六、待确认事项

已确认以上规则，无待确认事项。同环境重新带入时保留仍选中服务的分支；切换环境使用目标环境的默认分支。
