# 本地前后端开发计划 v0.4

日期：2026-10-20

状态：用户已授权开始前后端开发并启动；已确认将 v0.3 前端带入 GitHub 默认 main 分支，此后只在 main 迭代。

## 一、问题确认

当前仅为刷新即重置的前端演示，不能保存业务资料或调用 Jenkins。版本创建提前选择服务也不符合实际流程。

## 二、调整后的结果

创建项目及服务、项目内环境、版本 SQL 和配置后保存到本机。新建版本只填版本资料，最终服务与分支在发布时确定；从版本详情发布的记录关联当前版本，独立发布不强制选择版本。

全局管理前后端 Jenkins 连接，支持连接检查、读取任务参数、触发所选 Job、跟踪队列与构建、查看各服务结果。服务器和单一 MySQL 连接可保存凭据并测试；数据库备份独立发起，不随发布执行。

提供本机资料备份、外部 AI 查询与发布入口、Skill 使用说明和 stdio MCP。应用启动后浏览器可使用真实本地数据；附带启动、停止、状态和日志说明。

## 三、本期做 / 不做

完成上述可用本地版本及必要验证。首次启动为空工作台，演示数据不混入真实记录。

工具发布仍只触发已有 Jenkins；不执行版本 SQL、不修改远程配置、不进行 SSH 部署，不接入模型或 Nacos，不做业务库自动恢复。

## 四、前后端改动范围

前端沿用现有布局，接入业务 API，改正版本服务流程、凭据保存、发布进度、备份页和 AI 资料页。

后端使用 Node.js、SQLite，保存业务资料、版本资源与执行快照；秘密单独加密，接口不回传秘密。增加 Jenkins 客户端、SSH/MySQL 检查、独立备份、MCP 适配和进程脚本。

## 五、验证方式

后端测试覆盖持久化、凭据不泄漏、版本关联、请求校验、重复提交、队列/构建结果与重启恢复；Jenkins 使用受控本地测试服务验证，不触发实际项目。

检查前端构建和浏览器端创建、编辑、刷新保存、无版本发布入口、版本发布关联及错误提示。实测启动、停止、重启及就绪状态，最后保留应用运行。

## 六、待确认事项

本期开发已获授权，无阻塞确认项。真实 Jenkins、SSH、MySQL 的环境联调需用户在页面配置后进行，不能把受控验证报告为真实部署成功。
