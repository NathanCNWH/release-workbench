# Release Workbench 临时开发计划及确认清单

日期：2026-10-20

状态：待确认，尚未开始应用开发

## 一 问题确认

需要一个本地工具，将项目、环境、版本、代码分支、SQL、配置、备份、服务器和 Jenkins 联系起来，并提供 AI 可使用的部署入口。已确认采用自研路线，项目位于 `D:\git_rep\release-workbench`，建立同名 GitHub 私有仓库。

## 二 调整后的结果

用户可以打开一个版本看完整资源清单，选择环境预览并部署，查看每一步的结果和备份；同一版本在各环境保留独立发布记录。失败时明确显示已经完成的变更与待处理步骤，AI 与页面得到一致结果。

完整页面、字段、状态和场景见[功能设计说明书](功能设计说明书-v0.1.md)。

## 三 本期做与不做

本期按以下顺序交付，具体选项以第六节确认结果为准：

1. 本地启动、项目、环境、组件、连接与凭据。
2. 版本草稿、固定资源、就绪检查、版本比较。
3. 备份、SQL、配置、SSH、Jenkins 和持久化部署记录。
4. 失败核对、任务恢复、完整导入导出。
5. CLI、Skill、MCP 及端到端验收。

本期不做团队协作、复杂审批、服务器监控、在线终端、CI 引擎、Kubernetes 管理、自动全局回滚和生产数据库一键恢复。

## 四 前后端改动范围

前端新建项目工作台、项目详情、环境与连接、版本、部署详情、备份及设置页面。

后端新建业务 API、SQLite 管理存储、文件存储、任务 Worker 和外部系统适配器。CLI 与 MCP 复用业务服务；Skill 仅作为操作指引。技术与数据对象建议集中见功能设计附录，不在本节重复。

## 五 验证方式

先在受控 Git、SSH、MySQL 和 Jenkins 环境验证，再执行功能设计 A01 至 A24 验收。重点覆盖版本冻结、同版本跨环境、SQL 重复执行防护、外部任务失联、备份失败阻断、任务重启恢复、凭据脱敏和 AI 权限。

每阶段报告实现结果、自动测试和联调证据。生产连接与部署单独指定，不把示例运行或模拟结果作为真实部署成功。
