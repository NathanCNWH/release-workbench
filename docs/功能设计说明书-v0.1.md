# Release Workbench 完整功能设计说明书

版本：v0.1

日期：2026-10-20

状态：待需求确认

适用对象：项目使用者、开发人员、后续接入的 AI 工具

Release Workbench 用于在本地管理项目、环境、版本和发布所需资源。用户能够回答“这个版本修改了什么”“某环境当前运行什么”“发布前备份在哪里”“上次失败停在哪一步”，并能从页面或 AI 入口执行同一套部署流程。

产品采用自主设计的管理核心，连接现有 Git、SSH、Jenkins 和数据库工具。本文给出完整目标及首期建议，具体确认项统一放在《临时开发计划及确认清单》中。文中拟定的技术与范围不代表已经完成实现。

## 1 使用后能得到什么

### 1.1 一次完整使用过程

1. 新建“订单系统”项目，登记后端、前端等组件及其代码仓库。
2. 创建测试、生产环境，为环境绑定服务器、数据库、配置文件位置和 Jenkins Job。
3. 新建 `v1.2.0`，选择各组件的分支和固定提交，添加增量 SQL、配置更新和产物信息。
4. 查看变更清单，完成文件导入与连接检查，将版本标记为就绪。
5. 选择测试环境，预览部署步骤及影响对象，执行发布。
6. 查看各步骤的备份、执行状态、日志、校验结果和异常原因。
7. 将同一版本发布到生产，保留生产环境独立的备份和执行记录。
8. AI 可以查询这些资料、生成部署预览、执行被允许的计划并等待最终结果。

### 1.2 主要页面效果

打开项目即可看到以下信息：

| 信息 | 展示示例 |
| --- | --- |
| 当前版本 | 测试环境 v1.2.0 已验证；生产环境 v1.1.3 已验证 |
| 待发布版本 | v1.2.0，2 个组件、1 个 SQL、2 个配置变更 |
| 最近一次发布 | 生产环境执行失败，停在“配置上传”，后续步骤未执行 |
| 最近备份 | 数据库备份成功，来源部署 DEP-0008；可查看文件与校验信息 |
| 后续操作 | 查看版本、部署预览、重试计划、查看日志 |

“已验证版本”只在部署规定的验证步骤全部通过后更新。若只有部分步骤成功，页面同时显示最后完整成功版本和本次部分变更，不能把环境表现为完整停留在旧版。

## 2 产品定位与运行方式

### 2.1 使用范围

首期面向个人在一台 Windows 电脑管理多个项目及远程 Linux 服务器。管理数据、资源副本和执行记录保存在本机，浏览器访问本机工作台。远程 Git、Jenkins、服务器和数据库按各自连接方式访问。

应用关闭或电脑休眠后，本机不能保证继续执行任务。远端已经启动的 Jenkins 构建或命令可能继续运行；重新启动后应核对真实状态，再决定是否继续。

### 2.2 完整能力与阶段

| 能力 | 首期建议 | 后续扩展 |
| --- | --- | --- |
| 本地使用 | Windows 启动脚本、本机 Web 页面、数据目录可选择 | 原生桌面安装包、托盘与自动更新 |
| 基础管理 | 项目、组件、环境、连接资源、凭据引用 | 多人协作、团队权限、审批流 |
| 版本资源 | 固定提交、SQL、文本配置、产物、步骤、差异比较 | 自动发现工作区变更、Git 分支创建、版本依赖分析 |
| 数据库 | MySQL 8 连接、SQL 执行、业务库备份及下载 | PostgreSQL、更多数据库、图形化恢复向导 |
| 配置 | YAML、JSON、properties、普通文本文件 | Nacos、Apollo 等配置中心适配 |
| 发布 | Jenkins 与 SSH、串行步骤、锁定、失败处理、健康检查 | 定时发布、复杂并行编排、灰度与容器平台适配 |
| AI | 共用业务 API、CLI 与 Skill、本地 stdio MCP | 远程 MCP、多用户授权 |
| 数据保护 | 本机工作台备份、项目导入导出、恢复索引检查 | 异地存储、定时备份与自动保留策略 |

首期不建设完整 CI 平台、数据库管理 IDE、在线交互终端、Git 托管平台、服务器监控或 Kubernetes 管理系统。

## 3 页面与导航

```text
项目工作台
├─ 项目列表
└─ 项目详情
   ├─ 概览
   ├─ 环境
   │  └─ 环境详情：部署情况、资源绑定、检查结果
   ├─ 组件与仓库
   ├─ 版本
   │  └─ 版本详情：概要、组件、SQL、配置、产物、部署步骤、历史
   ├─ 部署记录
   │  └─ 部署详情：执行进度、日志、备份、核验结果
   └─ 备份与资源文件

全局设置
├─ 凭据
├─ AI 接入
├─ 数据与备份
└─ 本地运行设置
```

### 3.1 项目列表

支持新建、搜索、编辑、归档项目。项目卡片显示名称、说明、环境数量、待发布版本及最近部署结果。归档项目默认隐藏，其历史资料保留。存在部署、备份或版本引用时，首期不提供级联永久删除。

### 3.2 项目概览

环境以卡片展示，列出最后完整成功版本、最近执行状态和连接检查时间。快捷操作包括新建版本、进入环境、查看最近部署、进入备份。最近检查时间始终可见，不能把过期检测结果当作实时状态。

### 3.3 环境详情

顶部展示环境名称、类型、最后完整成功版本和当前未完成变更。下方分为服务器、数据库、配置位置、Jenkins、部署历史五个区域。用户可以修改绑定、测试连接、查看历史，但修改绑定不会改写已经完成的部署快照。

### 3.4 版本详情

顶部展示版本号、状态、变更摘要和资源完整性提示。各资源页签显示数量及是否准备完成。主要操作包括编辑草稿、比较版本、检查就绪条件、标记就绪、复制版本、部署预览和导出版本。

### 3.5 部署详情

左侧为按顺序排列的步骤，右侧展示当前步骤的状态、日志和结果。页面持续更新，并支持断线后补取日志。失败时直接展示步骤名、目标对象、退出码或外部任务状态、错误摘要及下一步可执行动作。

## 4 核心对象与关系

### 4.1 业务关系

```text
项目
├─ 组件 → 代码仓库
├─ 环境 → 服务器、数据库、配置位置、Jenkins 绑定
└─ 版本 → 组件提交、SQL、配置变更、产物、部署步骤
         └─ 部署记录 → 指定环境、执行快照、步骤结果、备份、验证结果
```

**版本归属于项目，部署记录归属于版本和环境。** 测试与生产共用同一版本的发布内容，各环境使用各自的目标地址、路径和凭据。

### 4.2 对象定义

| 对象 | 含义 | 示例 |
| --- | --- | --- |
| 项目 | 一组共同交付的软件与资源 | 订单系统 |
| 组件 | 项目中的独立部署单元 | order-api、order-web |
| 环境 | 一组确定的部署与数据目标 | 测试、生产 |
| 连接资源 | 服务器、数据库实例、Jenkins 等可访问目标 | 测试应用服务器 |
| 凭据 | 连接时使用的秘密或运行时秘密引用 | SSH 环境变量引用 |
| 版本 | 一次发布所需的确定资源集合 | v1.2.0 |
| 资源文件 | 已导入本机、可校验的 SQL、配置或产物 | migration.sql |
| 部署计划 | 版本在目标环境上的步骤及参数快照 | v1.2.0 发布到测试 |
| 部署记录 | 一次真实执行及其状态 | DEP-0008 |
| 备份 | 某个确定目标在某时点生成的恢复材料 | 数据库逻辑备份 |

### 4.3 基本规则

- 项目标识、环境标识、组件标识在各自范围内唯一；环境显示名称可修改，内部标识稳定。
- 版本号在项目内唯一，允许 `v1.2.0`、日期等命名，不按字符串排序判断版本新旧。
- 同一环境同一时刻只能有一个修改任务运行；共享同一数据库的不同环境，还必须竞争同一个目标库锁。
- 已被历史记录引用的连接资源和凭据只能停用，不能静默删除其历史说明。
- 资源文件导入本机后使用本机副本，原始文件变化不会悄悄改变已保存版本。

## 5 项目与组件管理

### 5.1 项目字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 名称 | 是 | 用户看到的项目名称 |
| 标识 | 是 | 稳定内部标识，可自动生成 |
| 说明 | 否 | 项目用途、负责人说明等 |
| 默认部署模板 | 否 | 创建版本时使用的步骤模板 |
| 状态 | 是 | 使用中、已归档 |

### 5.2 组件与仓库字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 组件名称和标识 | 是 | 识别独立服务或前端项目 |
| 仓库类型 | 是 | Git 地址或本地 Git 工作区 |
| 仓库地址或工作区路径 | 是 | 支持常规 GitHub、GitLab、自建 Git 地址 |
| 仓库凭据引用 | 按需 | HTTPS 或 SSH 认证 |
| 默认分支 | 否 | 仅作为新版本选择时的默认值 |
| 仓库内目录 | 否 | 支持一个仓库对应多个组件 |
| 部署方式 | 是 | Jenkins、SSH 文件发布或仅记录 |

首期支持测试仓库访问、刷新远程分支和 Tag、选择提交。GitHub/GitLab 仅作为普通 Git 源接入，不要求安装其平台插件。用户未提交的本地文件不会被自动打包；若要纳入版本，必须主动选择文件并形成资源快照。

## 6 环境和连接资源

### 6.1 环境字段

包含名称、标识、说明、类型（开发、测试、生产、自定义）、部署策略和环境变量。创建环境可复制同项目的已有环境绑定，但必须重新检查目标地址、数据库、目录和凭据引用。

复制环境只复制管理配置，不自动创建服务器、复制业务数据库或执行部署。

### 6.2 服务器连接

| 字段 | 说明 |
| --- | --- |
| 名称、主机、端口 | 记录服务器用途与 SSH 地址 |
| 认证方式 | 运行时环境变量、密码、私钥 |
| 凭据引用 | 可引用 `SSH_NAME` 与 `SSH_PWD`，不复制变量值 |
| 工作目录、发布目录、备份目录 | 环境内组件可覆盖具体路径 |
| 主机身份信息 | 保存首次核对的 SSH 主机指纹 |
| 连接检查 | 结果、错误摘要、检查时间 |

连接检查验证网络、认证和所需路径可用性，不启动业务进程。首期提供预定义部署命令的执行与日志，不提供在线交互终端。

### 6.3 数据库连接

包含逻辑名称、数据库类型、地址、端口、库名、字符集、TLS 设置和凭据引用。首期支持直接连接，以及通过已绑定 SSH 服务器建立隧道连接。

连接检查只读验证目标身份和权限。备份检查、SQL 执行检查分别显示，不能把“连接成功”当作“具备备份或变更权限”。数据库实际地址、库名和服务身份形成目标指纹，避免只根据环境显示名称判断目标。

### 6.4 Jenkins 连接

登记实例名称、URL、用户名和 API Token 引用；环境可绑定不同实例和 Job。支持 Folder 内完整 Job 路径及参数化任务。

首期对接现有 Job，维护参数映射、触发、等待、日志和结果；Jenkins 安装、插件管理、任意 Job XML 编辑和创建 Job 另行扩展。

## 7 版本和资源管理

### 7.1 创建版本

可创建空白版本，或从现有版本复制为草稿。字段包括版本号、标题、说明、基准版本和资源清单。基准版本用于对比，不强制所有项目遵循线性版本继承。

### 7.2 版本状态

| 状态 | 能做什么 | 转换条件 |
| --- | --- | --- |
| 草稿 | 编辑资源、调整步骤、检查与准备产物 | 新建或从其他版本复制 |
| 就绪 | 预览部署、执行、导出、复制 | 资源完整且通过就绪检查 |
| 已归档 | 查看历史与导出 | 无运行任务后归档 |

就绪版本内容冻结，不修改资源文件、提交或步骤。修改时复制为新草稿并使用新的版本号。部署成功、失败属于环境中的执行状态，不是版本的全局状态。

### 7.3 版本内组件

每个组件记录仓库快照、分支或 Tag 的显示名称、固定 Commit SHA、仓库内目录、部署方式和产物引用。分支只是选取入口，执行不能重新把同名分支当前 HEAD 当作原提交。

组件支持两种发布内容形式：

| 形式 | 就绪时固定什么 | 跨环境保证 |
| --- | --- | --- |
| 固定产物 | 文件或不可变产物引用、SHA256、来源构建 | 使用相同产物 |
| 固定源码 | Commit SHA、构建参数、构建方式 | 固定源码；重新构建的二进制不承诺相同 |

界面标注当前形式。已有 Jenkins 构建并部署 Job 可采用固定源码形式，但必须支持传入确定提交；只接受浮动分支且无法核验提交的 Job，不允许标记为可复现发布。

### 7.4 SQL 资源

每项包含名称、逻辑数据库目标、执行顺序、SQL 文件、校验和、说明、预期影响及可选核验 SQL。用户可以输入文本、导入本地文件，或选择固定 Git 提交中的文件。

SQL 文件内容固定到版本，实际目标库由环境绑定解析。脚本允许 MySQL 常用 DDL、DML 和多语句内容；执行器必须使用能正确处理脚本语法的数据库客户端，不能简单按分号拆分。事务能力按数据库及语句类型处理，不把 DDL 描述成可整体自动回滚。

同一目标数据库记录变更编号、文件校验和及结果。已成功执行的相同变更可跳过；编号相同但内容不同必须阻断。执行开始后失联或崩溃时进入待核验，不能自动重放 SQL。

### 7.5 配置资源

每项包含逻辑目标名称、格式、内容或文件、目标路径模板、更新方式、变量引用和校验和。首期更新方式为整个文件替换；结构化字段合并和补丁更新后续扩展。

- YAML、JSON 做格式校验，文本类显示内容差异。
- 部署前保存目标旧文件、是否原先存在、权限等恢复信息。
- 使用临时文件上传与同文件系统替换，按绑定规则保留文件权限。
- 配置中的环境差异通过变量引用解析，预览展示脱敏结果。
- 必填变量缺失时阻断部署，不写入未解析占位符。

Nacos、Apollo 等配置中心不伪装成本地文件，后续通过独立适配器提供发布、历史和恢复能力。

### 7.6 产物和辅助文件

支持 JAR、WAR、ZIP、前端压缩包及任意附件。记录文件名、大小、SHA256、来源、导入时间与所属版本。支持本地文件导入，以及绑定 Jenkins 构建编号与产物路径。

辅助说明附件只用于查看或下载，不自动执行。解压部署必须检查路径越界，不能把任意压缩包直接写入任意系统目录。

### 7.7 版本比较

比较两个版本的组件提交、资源新增删除、SQL 校验和、配置文本和步骤顺序。对同一版本在不同环境的部署，比较实际参数、目标指纹、产物及验证结果。内容脱敏，不展示凭据值。

## 8 Jenkins 集成行为

### 8.1 配置界面

选择实例、加载或输入 Job 全路径、读取支持的参数、设置固定参数和映射参数、测试访问。映射来源包括项目、版本、环境、组件 Commit、产物位置及手动部署参数。

密码参数通过凭据引用提供，不进入普通版本文件。Job 参数超出已支持类型时，展示不支持原因，不能静默使用 Jenkins 默认值。

### 8.2 执行记录

完整保存队列项 ID、构建编号、Job 地址、触发时间、运行时间、最终结果和日志游标。触发后从队列定位本次构建，不能通过“最新一次构建”猜测归属。

Jenkins 的成功、失败、中止、不稳定分别记录；部署步骤默认仅把成功视作通过。网络超时只说明本地暂未获得结果，重新查询已知队列或构建，不能立即再触发一次。

### 8.3 与 SSH 部署的关系

同一组件的一次部署选择一种负责交付的执行方式。若 Jenkins Job 已包含部署，工具不能再重复执行 SSH 文件发布；其他 SQL、配置、备份等步骤按计划显式排列，并在预览中说明由谁执行。

## 9 部署计划和执行

### 9.1 部署预览

选择就绪版本与环境后，生成具体计划。用户在一个页面看到目标服务器和库、组件提交或产物、SQL、配置差异、备份位置、步骤顺序、预计外部调用和就绪检查结果。

计划绑定版本内容摘要、环境绑定摘要与参数摘要。预览后修改目标、内容或参数，原计划失效并需重新生成。凭据只保留引用，运行时读取有效秘密。

### 9.2 首期步骤类型

| 类型 | 输入 | 成功依据 |
| --- | --- | --- |
| 连接与前置检查 | 目标、依赖、路径、工具 | 检查项通过 |
| 数据库备份 | 数据库、范围、输出位置 | 客户端成功、文件生成并记录校验信息 |
| 配置和文件备份 | 目标文件清单 | 文件或“不存在”状态记录完成 |
| SQL 执行 | 固定脚本、逻辑库、核验规则 | 执行结果和规定核验通过 |
| 配置上传 | 固定内容、目标路径、变量 | 写入及校验通过 |
| Jenkins 调用 | Job、固定参数、超时 | 本次构建满足成功规则 |
| SSH 文件发布 | 产物、目标路径、切换方式 | 上传校验和版本切换完成 |
| SSH 命令 | 已保存模板、参数、超时 | 退出码及可选结果规则通过 |
| HTTP 健康检查 | URL、超时、重试、响应条件 | 在规定时间内符合条件 |

步骤默认串行执行，用户可以调整顺序和超时。模板可提供“检查 → 备份 → 变更 → 部署 → 验证”的初始顺序，实际业务顺序由项目确定。健康检查未配置时，页面只报告部署步骤完成，不冒充业务健康已验证。

### 9.3 执行状态

部署状态：排队中、执行中、成功、失败、取消中、已取消、待核验。

步骤状态：未开始、执行中、成功、失败、已跳过、已取消、待核验。待核验表示外部可能已执行，但本机无法确认结果。只有成功和按规则可跳过的步骤可让计划继续。

### 9.4 失败处理

| 情况 | 默认行为 |
| --- | --- |
| 前置检查或要求的备份失败 | 停止，后续变更不执行 |
| SQL、配置、发布步骤失败 | 停止，保留已完成步骤和环境部分变更 |
| 查询或连接短暂失败 | 允许有限重试查询，不重复发起写动作 |
| 用户重复点击或 AI 重复请求 | 同一幂等键返回原执行记录 |
| 外部任务结果未知 | 待核验，阻止同一目标继续修改 |
| 本机重启 | 恢复记录，查询可追踪外部任务；不能确认的步骤待核验 |

首期不做失败后的自动全局回滚。程序或配置回退与数据库恢复分开管理，避免把恢复业务数据等同于切换程序版本。

### 9.5 取消与重试

取消会阻止尚未开始的步骤，并尝试中止可中止的外部任务；不能保证已经提交的 SQL、文件写入或远端命令撤销。中止结果必须核实。

重试生成新的执行记录，关联原任务并展示继承的成功步骤。仅明确可重复且状态已知的步骤允许重跑；SQL 或命令待核验时，用户先登记核对结果和依据，再生成后续计划。

### 9.6 环境当前状态

完成规定验证后，更新环境最后完整成功部署。失败后保留“上次完整成功版本”和“本次实际完成的变更”两部分。用户不能通过手动修改显示版本号，掩盖尚未完成的发布。

## 10 备份和恢复资料

### 10.1 备份种类

| 种类 | 内容 | 用途 |
| --- | --- | --- |
| 数据库连接信息快照 | 脱敏地址、库名、类型、凭据引用、目标指纹 | 追踪当时连接的是哪个库 |
| 业务数据库备份 | 指定业务库的逻辑备份及生成记录 | 为独立恢复提供材料 |
| 配置和文件备份 | 变更前文件、存在状态、权限和校验和 | 配置或程序文件回退 |
| 工作台备份 | 管理数据库、版本资源、备份索引及运行设置 | 恢复本地工具自身 |

数据库连接信息快照不能代替业务数据备份；单独复制工作台数据库文件也不能代替完整工作台备份。

### 10.2 备份记录

每条记录包含项目、环境、目标、类型、来源部署、开始结束时间、文件位置、大小、SHA256、生成状态和可用性。文件生成成功与恢复验证通过分开显示。

支持手动备份和部署步骤自动备份。首期默认保存到用户选择的本地数据目录；经 SSH 在服务器生成时，必须传回本机并核对后才标记为完整本地备份。远端临时备份未传回时明确显示位置和传输状态。

首期不自动删除数据库备份。用户删除前展示依赖的部署与版本，明确区分只移除索引和删除实际文件。

### 10.3 恢复边界

首期支持备份下载、核验、原配置文件的显式恢复，以及完整工作台恢复。业务数据库提供恢复材料和目标说明，不提供自动覆盖生产库的一键恢复；图形化数据库恢复列入后续范围。

恢复工作台前检查格式、资源文件和校验和，并先备份当前数据。恢复中不能并行运行部署。迁移到另一台电脑时，需要单独的凭据恢复材料或重新填写凭据。

## 11 环境变量和凭据

普通变量用于目录、端口、应用参数等环境差异；秘密变量用于密码、Token、私钥。普通变量可进入脱敏导出，秘密内容默认不进入版本包、页面日志或 AI 返回值。

凭据支持新增、更新、测试、停用和查看引用位置。服务器可直接选择“使用运行环境中的 SSH_NAME / SSH_PWD”。变量缺失时返回具体缺失名称，不弹出隐藏交互式登录，也不把空值当作有效凭据。

部署开始时解析凭据，执行记录保存凭据标识及版本标记，不保存秘密明文。更新凭据影响后续访问，不改写旧版本的发布内容和目标快照。

## 12 AI 接入

### 12.1 页面和 AI 的一致性

页面、CLI、Skill 和 MCP 都调用同一套业务服务。AI 不直接修改 SQLite、拼接未保存的部署脚本或绕过计划执行。所有入口产生相同的部署记录和错误码。

### 12.2 首期能力

| 能力 | 输入 | 输出 |
| --- | --- | --- |
| 查询项目与环境 | 名称或 ID | 脱敏详情、当前部署情况 |
| 管理草稿版本 | 项目、版本和选定资源 | 草稿、资源清单、检查结果 |
| 比较版本 | 两个版本 | 组件、SQL、配置和步骤差异 |
| 生成部署预览 | 版本、环境、参数 | 计划 ID、摘要、检查结果 |
| 执行计划 | 计划 ID、摘要、幂等键 | 部署 ID |
| 等待与查询 | 部署 ID、日志游标 | 步骤状态、脱敏日志、最终结果 |
| 创建备份 | 明确数据库或文件目标 | 任务 ID、备份结果 |

### 12.3 Skill

提供随项目版本发布的 Skill 和 CLI 使用说明。AI 根据项目和环境查询资源，生成计划，执行允许的计划，轮询或等待任务结束，最后报告结果。Skill 不保存秘密值，也不自动安装到用户所有 AI 客户端；用户选择目标客户端后安装。

### 12.4 MCP

首期提供本地 stdio MCP，支持只读、草稿管理和部署执行三类能力范围。令牌可限制项目、环境和允许动作；未启用的动作不暴露给客户端。

生产环境是否允许 AI 直接执行按确认清单决定。需要人工确认的环境返回待确认计划，AI 不能替代用户完成该确认；允许自动执行的环境可完成“预览 → 执行 → 等待”的一次请求。人工确认与当前计划摘要绑定，计划变化后不能沿用旧确认。

## 13 导入导出与数据迁移

支持导出项目配置、单个版本包和完整工作台备份，三种用途分别提供入口。项目配置不包含实际业务库数据；版本包包含固定资源和清单，秘密只保留引用占位。

导入先展示检查结果和冲突清单，再一次性提交管理数据。有同名标识时选择重命名、取消或显式替换可替换对象；不能默认覆盖。就绪版本和历史执行记录不能被同名导入重写。

导入失败时不生成一半项目或部分资源引用。文件先进入临时区域，通过校验后再提交引用；无效文件清理不影响已有数据。

## 14 本地设置和使用体验

- 首次运行选择数据目录，默认使用用户本地应用数据目录，与源码和 Git 仓库分离。
- 首期默认仅监听 `127.0.0.1`，不向局域网或公网提供服务。
- 一条启动命令或启动脚本打开工作台，支持检查端口占用和查看运行状态。
- 列表支持按项目、环境、版本、结果及时间搜索筛选，长记录分页加载。
- 文件上传展示大小和进度；单文件上限首期建议为 2 GiB，可在设置中调整并在上传前提示。
- 执行日志持续显示；页面刷新后恢复任务，不重新发起发布。
- 时间以本地时区显示，持久化保存标准时间和时区信息。
- 数据目录容量不足时在生成备份或上传前返回明确错误，不能生成“成功”的空文件记录。

## 15 验收场景

所有验收先使用临时目录、虚构凭据、测试数据库及受控 SSH/Jenkins 环境。真实生产环境连接或部署需要单独指定目标。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 新建项目和两个环境 | 两个环境资源独立，可在概览看到各自状态 |
| A02 | 一个项目包含前后端仓库 | 版本可分别固定两个组件提交 |
| A03 | 就绪后源分支继续提交 | 部署仍使用固定 SHA，或者明确阻断无法满足的 Job |
| A04 | 版本文件原件变化 | 已导入副本与校验和不变 |
| A05 | 同版本发布测试和生产 | 发布内容一致，目标与执行记录各自独立 |
| A06 | 版本比较 | 可看见组件、SQL、配置和步骤变化 |
| A07 | MySQL 连接与备份 | 文件可取回且具有来源、大小和校验和；不冒称已恢复验证 |
| A08 | 备份失败 | SQL、配置和程序变更均未执行 |
| A09 | SQL 执行成功后重试 | 相同目标和校验和的已完成变更不重复执行 |
| A10 | SQL 执行中断电 | 重启后待核验，阻止自动重放及同目标并发变更 |
| A11 | 配置变量缺失 | 部署前阻断，错误指出变量名 |
| A12 | 配置发布失败 | 原文件和中间状态可追踪，不误标整体成功 |
| A13 | Jenkins 并发构建 | 通过队列 ID 关联本次构建，不取错他人结果 |
| A14 | Jenkins 已触发但本地超时 | 查询原任务，不重复触发 |
| A15 | 同环境连续发起两次修改 | 第二次排队或被明确拒绝，无并发写入 |
| A16 | 不同环境共享同一个库 | 同库修改锁生效 |
| A17 | 健康检查失败 | 环境展示部分变更，最后完整成功记录不被覆盖 |
| A18 | 取消部署 | 未开始步骤不执行；已执行动作的结果如实保留 |
| A19 | AI 重复执行同一请求 | 返回同一个部署 ID |
| A20 | AI 权限与生产策略 | 不允许的动作明确拒绝，允许的动作记录来源 |
| A21 | 秘密脱敏 | 页面、日志、导出、API 和 MCP 不返回秘密值 |
| A22 | 工作台完整备份恢复 | 管理记录和版本文件可恢复，凭据恢复边界明确 |
| A23 | 导入冲突或文件损坏 | 整体失败且已有数据不变 |
| A24 | 退出重启与页面断线 | 可恢复记录和日志，外部未知结果保持待核验 |

## 16 交付内容

首期交付本地应用源码、启动与停止脚本、配置示例、数据库迁移、CLI、Skill、本地 MCP、测试结果和使用文档。另提供一套虚构示例项目，演示两个环境、两个组件和一个完整版本。

使用文档覆盖首次启动、连接配置、版本准备、部署、失败核对、备份导出、AI 接入和数据目录迁移。最终报告分别说明功能实现、自动验证、受控环境联调与真实环境验证结果。

## 附录 A 技术实现建议

技术选择在需求确认后锁定依赖版本。建议前后端统一 TypeScript，减少本地安装的运行时数量。

| 部分 | 建议 |
| --- | --- |
| 前端 | React、TypeScript、Vite、Ant Design |
| 后端 | Node.js 24 LTS、Fastify、TypeScript |
| 管理存储 | SQLite、本地文件存储、显式数据库迁移 |
| 执行调度 | 独立 Worker 进程，数据库持久化任务与步骤状态 |
| 日志 | 文件分段保存与数据库索引，通过 SSE 提供更新 |
| Git | 调用已安装的 Git，参数数组传递，不拼接任意 Shell 字符串 |
| SSH | 成熟 SSH/SFTP 库，复用相同连接和日志接口 |
| Jenkins | Remote Access API，保留队列与构建定位 |
| MySQL | 驱动用于检查；完整脚本和备份使用兼容原生客户端 |
| AI | CLI 封装业务 API，Skill 指导使用，MCP 适配相同业务服务 |

SQLite 数据目录要求本地磁盘，不放网络共享盘。备份使用一致性备份方式或短暂暂停写入，不在 Worker 运行时只复制单个 `.db` 文件。未来多人并发或常驻服务器部署再评估 PostgreSQL。

Windows 秘密采用加密存储，主密钥由系统凭据保护能力保管；迁移用独立加密恢复包或重新填写。后端校验本地会话、Origin 与 AI 令牌，不能把“仅本地监听”当作不需要访问控制。

MySQL 客户端可以位于本机或经 SSH 调用的受控服务器，连接检查需报告实际使用的位置和版本。秘密通过受限临时配置或客户端支持的安全输入方式传递，不能写进命令行日志。备份的一致性条件、表类型和权限不足必须在结果中说明。

## 附录 C API 和 AI 接口建议

| 范围 | 示例接口 | 用途 |
| --- | --- | --- |
| 项目与环境 | `/api/projects`、`/api/environments` | 管理基础对象 |
| 组件和连接 | `/api/components`、`/api/connections` | 管理非秘密连接资料 |
| 凭据 | `/api/credentials` | 写入或更新秘密，响应仅含描述与引用 |
| 文件和版本 | `/api/files`、`/api/releases` | 导入资源、管理与检查版本 |
| 部署预览 | `POST /api/deployment-plans` | 返回计划、摘要和检查结果 |
| 部署执行 | `POST /api/deployments` | 使用计划 ID、摘要与幂等键执行 |

CLI 示例为 `release-workbench release inspect`、`deploy plan`、`deploy run`、`deploy wait`、`backup create`。CLI 提供 JSON 输出、稳定退出码和可定位的错误，避免 AI 解析页面文字。
