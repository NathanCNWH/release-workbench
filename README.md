# Release Workbench 项目发布工作台

Windows 本地 Web 工具，管理项目、服务、环境及版本资料，并通过已有 Jenkins Job 发布所选服务。React 前端 + Node.js 后端 + 本机 SQLite，单人单机使用。

新建版本可选涉及服务，也可先留空，后续在草稿的“涉及服务”勾选并保存；过程中维护 SQL 和配置差异。实际发布从部署记录页面入口选择环境、版本、服务和分支。勾选多个版本会自动带入关联服务并去重，之后可手动增减；增减版本或切换环境会重新带入，仅调整合并顺序保留手动选择。无法发布的关联服务显示原因，未登记服务的版本可手动选择。SQL/配置冲突由人工处理，保存来源和最终内容快照；原版本保留，也可不选版本独立发布。SQL 及配置由人工处理，工具自身不执行或推送。

## 本地目录

`D:\git_rep\release-workbench`

## 项目笔记

在左侧“项目笔记”创建、编辑或删除当前项目的笔记。正文支持 Markdown 和普通文本，可切换预览；按标题或正文搜索，列表按最近更新时间排列。修改后点“保存笔记”；切换笔记、项目、页面或刷新关闭时，会提醒处理未保存内容。其他窗口修改同一篇笔记时保留当前草稿，通过“加载最新内容”处理冲突。

笔记保存在本机 SQLite，包含在“工作台资料”备份中；旧数据升级自动建立空笔记集合，不影响原有资料和密钥。用户笔记正文不提交 GitHub。本期不提供笔记专用 MCP 工具、附件或同步功能。

## 启动与停止

需要 Node.js 24 或以上。在项目目录执行：

```powershell
npm run start:background
```

打开 <http://127.0.0.1:4173/>。也可双击根目录 `启动.cmd`；后台运行，无需保持启动窗口打开。

```powershell
npm run stop
npm run status
```

停止也可双击 `停止.cmd`。脚本校验目标实例和进程归属，不会结束其他 Node 程序。停止本机应用不会中止远端 Jenkins。

启动脚本按 lock 文件安装依赖、构建前端并等待就绪。数据在 `data/`，日志在 `data/logs/`；密码、Token、私钥单独加密。迁移时保留完整数据目录及 `.master-key`。本仓库不保存实际数据、凭据或备份。

项目维护服务和 Git；在服务管理拖动手柄排序，也支持聚焦手柄后按 Alt + ↑ / ↓，顺序保存并用于环境、版本和发布列表。环境内独立新增主机，在“服务与主机”将左侧服务连接点拖到右侧主机，或依次点击两端。解除连线保留主机，删除主机需确认并清理关系，编辑后保存环境。环境共用一份路径和一个数据库。全局共用前后端两套 Jenkins 连接，环境按服务绑定 Job 及参数。可读取 Job 公开的分支选项；插件未公开时手动维护。

数据库备份独立使用 mysqldump，支持 gzip 下载及 SHA256；工作台资料可导出为不含连接凭据的 JSON。外部 AI 页面提供 stdio MCP 配置和 Skill 下载，支持资料增删改查、版本合并和发布，没有内置模型。

## 开发与验证

```powershell
npm ci
npm test
npm run build
npm run dev
```

开发模式前端 5173、后端 4175；日常后台服务为 4173。GitHub 此后在默认 main 分支迭代。

受控测试使用虚构资料和 Mock Jenkins，覆盖 API、持久化、版本范围、Jenkins 生命周期、重复提交保护及 MCP；真实连接资料仅保存在用户本地，不作为仓库测试数据。真实 Job 的只读核验不代表实际发布成功。历史离线 HTML 是评审样稿，真实应用需访问本机服务。
