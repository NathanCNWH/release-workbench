# Release Workbench 项目发布工作台

本地项目、环境、版本与发布资源管理工具。将代码仓库、分支和提交、SQL、配置变更、服务器、数据库备份、Jenkins 与部署记录关联起来，并向 AI 提供统一的操作入口。

**当前阶段：前端样稿评审。使用内存示例数据，不连接真实服务；用户确认页面后再开发后端。**

- [完整功能设计](docs/功能设计说明书-v0.1.md)
- [最新需求确认记录](docs/需求确认记录-v0.3.md)
- [本次前端调整范围](docs/临时修改计划-项目服务与Jenkins发布-v0.3.md)

项目采用自主设计的管理核心。已确定采用 Windows 本地 Web，单人单机使用。发布只代替人工触发已有 Jenkins Job；SQL 执行和配置更新由人工完成。

## 本地目录

`D:\git_rep\release-workbench`

## 运行前端样稿

需要 Node.js 24 和 npm。在项目目录执行：

```powershell
npm install
npm run dev
```

打开 `http://127.0.0.1:4173/`。也可运行根目录的 `启动前端样稿.cmd`。

```powershell
npm run build
npm run export:preview
```

第二条命令生成 `output/preview/Release-Workbench-前端样稿.html`，可离线直接打开，无需运行服务。

页面包括项目概览、项目服务与 Git 清单、版本与 SQL/配置差异、环境连接、全局 Jenkins 设置、服务发布演示、逐服务构建记录、独立备份索引和外部 AI 资料。新建项目时可添加服务，版本直接选择；环境内可维护多台服务器、一份共用部署路径和一个数据库连接。所有编辑在刷新后重置。

从「部署记录 → 预览发布」选择环境、勾选服务；支持分支参数的 Job 可选择分支，其余使用 Job 自身配置。Job 及固定参数在「环境连接 → 服务发布任务」维护，账号按服务类型引用全局前端/后端 Jenkins。无需先创建版本或标记就绪；入队、构建与最终结果分别演示。

当前没有后端、SQLite、真实远程连接、备份文件、CLI 或 MCP，也没有聊天、模型配置和模型调用。分支为手动维护的示例选项，尚未读取真实 Job。即便后续开发真实发布，工具自身也不执行 SQL、不更新配置、不通过 SSH 部署；实际部署由已有 Jenkins Job 完成。

## 页面确认

请确认页面布局、字段和操作流程。外部 AI 已确认允许读取资料并调用一键发布；项目本身不接入模型。当前只展示资料与接口能力，真实业务开发等待页面确认。

本仓库不保存服务器密码、数据库密码、Jenkins Token、SSH 私钥、实际数据库备份或生产配置。
