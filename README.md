# Release Workbench 项目发布工作台

本地项目、环境、版本与发布资源管理工具。将代码仓库、分支和提交、SQL、配置变更、服务器、数据库备份、Jenkins 与部署记录关联起来，并向 AI 提供统一的操作入口。

**当前阶段：前端样稿评审。使用内存示例数据，不连接真实服务；用户确认页面后再开发后端。**

- [完整功能设计](docs/功能设计说明书-v0.1.md)
- [最新需求确认记录](docs/需求确认记录-v0.2.md)
- [本次前端样稿范围](docs/临时修改计划-前端样稿-v0.2.md)

项目采用自主设计的管理核心，后续复用 Git、SSH、Jenkins 和数据库原生工具执行任务。已确定采用 Windows 本地 Web，单人单机使用。

## 本地目录

`D:\git_rep\release-workbench`

## 运行前端样稿

需要 Node.js 24 和 npm。在项目目录执行：

```powershell
npm install
npm run dev
```

打开 `http://127.0.0.1:4173/`。也可运行根目录的 `启动前端样稿.cmd`。

```powershell
npm run build
npm run export:preview
```

第二条命令生成 `output/preview/Release-Workbench-前端样稿.html`，可离线直接打开，无需运行服务。

页面包括项目概览、项目列表、版本与 SQL 差异、配置、组件、环境连接、发布流程演示、部署日志、备份索引和外部 AI 资料。支持在页面中新建项目与日期版本、编辑草稿资源、保存环境字段、复制和导出资料。所有编辑在刷新后重置。

当前没有后端、SQLite、真实远程连接、SQL 执行、备份文件、CLI 或 MCP，也没有聊天、模型配置和模型调用。连接检查、发布和备份按钮均明确说明演示范围。

## 页面确认

请确认页面布局、字段和操作流程。外部 AI 已确认允许读取资料并调用一键发布；项目本身不接入模型。当前只展示资料与接口能力，真实业务开发等待页面确认。

本仓库不保存服务器密码、数据库密码、Jenkins Token、SSH 私钥、实际数据库备份或生产配置。
